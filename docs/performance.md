# ביצועים — תוצאות שנמדדו

**כלי:** Lighthouse 12, build של Production (`next start`), Chromium headless. מובייל = ההגדרות של Lighthouse (Moto G Power, 4G איטי מדומה, האטת CPU ×4). דסקטופ = `--preset=desktop`.

**סייג חשוב:** הבדיקה נערכה בסביבה סגורה, שבה ה-CDN של Shopify חסום. לכן **תמונות המוצרים לא נטענו** (השרת החזיר שגיאה לכל תמונה). בעמודים שבהם התמונה היא האלמנט הגדול ביותר, ה-LCP האמיתי יושפע מזמן טעינת התמונה. הוא צריך להימדד שוב באתר הסופי, אחרי `catalog:mirror-images`. אלה מדידות מעבדה, לא נתוני שטח של משתמשים (CrUX).

## מה נשאר בדף הבית במובייל
ה-TBT (270–500ms) מגיע בעיקר מ-React/Next (framework) ומ-GSAP (נטען דינמית, רק בדף הבית). אפשרויות להמשך, לפי סדר תועלת:
1. למדוד באתר האמיתי עם תמונות (ייתכן שהתמונה תהיה ה-LCP, עם `priority`).
2. לטעון את GSAP רק כשהסיור נכנס לתצוגה (`IntersectionObserver`), ולא בטעינת הדף.
3. להפוך את חלק הטקסט של הפתיח לרכיב שרת, ולהשאיר רכיב לקוח רק לתמונה ולאנימציה.

## מדידה חוזרת
```bash
npm run build && npm start
npx lighthouse http://localhost:3000/ --only-categories=performance,accessibility,best-practices,seo
```
אחרי העלייה לאוויר: PageSpeed Insights (נתוני שטח אחרי כ-28 יום) ו-Core Web Vitals ב-Search Console. היעדים לשטח (אחוזון 75): LCP ≤ 2.5 ש׳, INP ≤ 200ms, CLS ≤ 0.1.

# תשלומים

## מצב נוכחי
`PAYMENT_PROVIDER=mock`: ספק בדיקה שלא מזיז כסף. הקופה מציגה "מצב בדיקה" ודף תשלום מדומה.

**הגנה:** בגרסת Production השרת **מסרב לעלות** עם תשלומי בדיקה, גם עם הספק המדומה וגם עם ה-sandbox של PayPlus (שמקבל כרטיסי בדיקה ציבוריים). חריג אחד: `ALLOW_TEST_PAYMENTS=true` **וגם** כתובת אתר `localhost` או `*.vercel.app` (Preview). בדומיין האמיתי זה לא אפשרי.

## הספק המומלץ: PayPlus
ישראלי, דף תשלום מתארח (פרטי כרטיס לא עוברים בשרת שלנו), ומפיק חשבוניות. המימוש: `src/lib/payments/payplus.ts`.

- **מאושר בתיעוד של PayPlus:** כרטיס אשראי ו-Google Pay בדף התשלום.
- **מוצעים כמוצרים של PayPlus:** Bit ו-Apple Pay. צריך לוודא בחשבון שלכם שהם זמינים בדף התשלום.
- הטקסט "אמצעי תשלום" בקופה נלקח מ-`paymentMethods` ב-`src/config/site.ts`. ברירת המחדל היא כרטיס אשראי בלבד. מוסיפים שם כל אמצעי רק אחרי שהופעל בפועל.

### מה צריך מבעל העסק
1. חשבון סוחר ב-PayPlus (כולל הסכם סליקה עם חברת אשראי).
2. מפתחות API לסביבת **הבדיקות** (sandbox) ואחר כך ל-Production: `API Key`, `Secret Key`, `Payment Page UID`.
3. החלטה על אמצעי התשלום שיוצגו בדף (כרטיס, Bit, ארנקים דיגיטליים), הפעלתם בממשק PayPlus ועדכון `paymentMethods` ב-`src/config/site.ts`.
4. אם רוצים חשבונית אוטומטית: הגדרת מודול החשבוניות ב-PayPlus.

### הגדרה
```env
PAYMENT_PROVIDER=payplus
PAYPLUS_API_KEY=...
PAYPLUS_SECRET_KEY=...
PAYPLUS_PAYMENT_PAGE_UID=...
PAYPLUS_BASE_URL=https://restapidev.payplus.co.il   # חובה. sandbox (רק ב-Preview עם ALLOW_TEST_PAYMENTS=true); ב-Production: https://restapi.payplus.co.il
NEXT_PUBLIC_SITE_URL=https://<הדומיין>               # חובה: מכאן נבנות כתובות החזרה וה-callback
```
ה-callback נשלח אוטומטית בכל בקשת תשלום: `https://<הדומיין>/api/payments/payplus/webhook`.

### רשימת בדיקות לפני Go-Live (ב-sandbox)
התיעוד הציבורי של PayPlus לא מציג את מבנה התשובות במלואו. לכן **חובה** להריץ את המסלול המלא מול ה-sandbox עם המפתחות שלכם ולוודא:
- [ ] יצירת דף תשלום (`PaymentPages/generateLink`) מחזירה `payment_page_link` ו-`page_request_uid`.
- [ ] בתשלום מוצלח מגיע callback עם header בשם `hash` ו-`user-agent: PayPlus`, והחתימה מאומתת (ב-`payment_events` רואים `signatureValid = true`).
- [ ] בדיקת הסטטוס (`PaymentPages/ipn` עם `payment_request_uid`) מחזירה `status_code: "000"`, `amount` בשקלים ו-`more_info` = מזהה ההזמנה. אם שמות השדות שונים, מעדכנים את `verifyPayment` ב-`payplus.ts`.
- [ ] ההזמנה עוברת ל"שולמה" רק אחרי האימות, והמלאי יורד.
- [ ] תשלום שנדחה → "התשלום נכשל". ביטול בדף התשלום → חזרה לקופה.
- [ ] callback כפול לא יוצר חיוב או הורדת מלאי כפולים.
- [ ] עסקה אמיתית קטנה ב-Production, ואחריה זיכוי.

**עד שהבדיקות האלה עוברות, לא מפעילים חיוב אמיתי.**

## איך התשלום מאובטח
- **פרטי כרטיס לא נשמרים ולא עוברים בשרת.** הלקוח מקליד אותם בדף של PayPlus.
- **הסכום נקבע בשרת:** מחירים ומשלוח מחושבים מחדש במסד בעת יצירת ההזמנה.
- **Webhook:**
  - חתימת HMAC-SHA256 נבדקת בהשוואה בזמן קבוע, ונדחית בלי מפתח סודי.
  - גם עם חתימה תקינה, **השרת שואל את PayPlus ישירות** מה סטטוס העסקה, ולא סומך על גוף ההודעה.
  - ההזמנה מסומנת "שולמה" רק אם הסכום והמטבע זהים בדיוק לסכום ההזמנה. אחרת נרשמת אזהרה לבדיקה ידנית.
- **מניעת כפילויות ומצבים שגויים:**
  - הודעה שכבר טופלה לא מטופלת שוב (הגנה מפני שליחה חוזרת או replay).
  - רק הזמנה שממתינה לתשלום (או שהתשלום שלה נכשל) יכולה לעבור ל"שולמה". אישור תשלום שמגיע להזמנה שבוטלה או זוכתה לא משנה אותה. במקום זה נכתבת בהזמנה הערה "לבדיקה וזיכוי".
  - תשלום שני (עסקה אחרת) להזמנה ששולמה כבר מסומן בהערה "ייתכן חיוב כפול".
  - לכל הזמנה נפתח דף תשלום אחד. שליחה חוזרת של הקופה מחזירה את אותו דף, ולא יוצרת בקשת תשלום נוספת.
  - שורת ההזמנה ננעלת בזמן העדכון.
  - מזהה עסקה יכול להשתייך להזמנה אחת בלבד.
  - לחיצה כפולה בקופה מחזירה את אותה הזמנה.
- **אם ה-webhook לא הגיע:**
  - עמוד החזרה מהתשלום בודק את הסטטוס מול PayPlus.
  - בניהול יש כפתור "בדיקת התשלום מול חברת הסליקה".
- **רישום:** נתוני תשלום נשמרים ב-`payment_events` אחרי הסרת כל שדה שנראה כמו פרטי כרטיס.

## החלפת ספק סליקה
למשל Cardcom, Tranzila או Grow:
1. כותבים מחלקה חדשה ב-`src/lib/payments/<ספק>.ts` שמממשת את `PaymentProvider` (`types.ts`):
   - `createPayment` — יצירת דף תשלום והחזרת כתובת להפניה.
   - `parseWebhook` — אימות חתימה וחילוץ מזהים.
   - `verifyPayment` — שאילתה ישירה לספק על הסטטוס.
2. רושמים אותה ב-`src/lib/payments/index.ts` ומוסיפים את הערך ל-`PAYMENT_PROVIDER` ב-`src/config/env.ts` וב-`.env.example`.
3. מוסיפים את הדומיין של הספק ל-`form-action` ב-CSP (`next.config.ts`) אם הוא משתמש בטופס POST.
4. מריצים את בדיקות היחידה (`tests/unit/payplus.test.ts` הוא תבנית טובה) ואת רשימת הבדיקות שלמעלה.

כל שאר המערכת (הזמנות, מלאי, מיילים) לא משתנה.
